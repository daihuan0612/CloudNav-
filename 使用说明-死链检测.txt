死链检测功能 - 使用说明
========================

一、需要替换/新增的 3 个文件（放到你 fork 的 CloudNav 仓库对应位置）：

  1. functions/api/check.ts          【新增】海外探测端点（Cloudflare Worker 边缘节点）
  2. components/DeadLinkCheckModal.tsx 【新增】检测面板组件
  3. App.tsx                         【修改】集成（侧边栏新增"检测"按钮）

  放置后 commit + push，Cloudflare Pages 会自动重新部署。
  （不会 git 的话：GitHub 网页打开对应目录 → Add file → Upload files，
    同名文件直接覆盖，分别上传这 3 个文件即可）

二、使用方式

  部署完成后打开导航站 → 左侧边栏底部出现"检测"按钮（导入/备份/检测/设置）：
  1. 先登录（输入访问密码）
  2. 点"检测"→"开始检测"
  3. 等待约 1-2 分钟（本地 + 海外双端探测 96 个链接）
  4. 结果分四类：
     - 正常（绿）：服务器活着，你当前网络也能访问
     - 可能被墙（黄）：海外能访问，但你当前网络打不开 —— 开 VPN 就能用，不是死链
     - 疑似死链（红）：本地和海外都打不开，大概率真的挂了
     - 未测（灰）：通常是因为后端调用失败或该链接为 http://（浏览器安全限制无法本地探测）
  5. 每条结果右侧有删除按钮，可直接清理确认的死链

三、判定逻辑（重要）

  - 双端探测：你的浏览器（反映你当前网络/VPN 状态）+ Cloudflare Worker（海外节点）
  - 只有"本地打不开 + 海外也打不开"才判为"疑似死链"
  - "本地打不开 + 海外能开" → "可能被墙"，不会误杀
  - "本地能开 + 海外打不开" → 仍算"正常"（例如国内才能访问的网站）
  - http:// 链接受浏览器混合内容限制，本地无法探测，只看海外结果

四、注意事项

  - 检测结果实时计算，不写入数据库
  - 检测需要访问密码（x-auth-password 鉴权，与其他接口一致）
  - 海外探测每个链接超时 8 秒，96 个链接完整一轮约 1-2 分钟
  - 如果"未测"数量很多，先确认已登录，再重新检测
